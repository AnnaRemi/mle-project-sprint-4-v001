# Подготовка виртуальной машины

## Склонируйте репозиторий

Склонируйте репозиторий проекта:

```
git clone https://github.com/yandex-praktikum/mle-project-sprint-4-v001.git
```

## Активируйте виртуальное окружение

Используйте то же самое виртуальное окружение, что и созданное для работы с уроками. Если его не существует, то его следует создать.

Создать новое виртуальное окружение можно командой:

```
python3 -m venv env_recsys_start
```

После его инициализации следующей командой

```
. env_recsys_start/bin/activate
```

установите в него необходимые Python-пакеты следующей командой

```
pip install -r requirements.txt
```

### Скачайте файлы с данными

Для начала работы понадобится три файла с данными:
- [tracks.parquet](https://storage.yandexcloud.net/mle-data/ym/tracks.parquet)
- [catalog_names.parquet](https://storage.yandexcloud.net/mle-data/ym/catalog_names.parquet)
- [interactions.parquet](https://storage.yandexcloud.net/mle-data/ym/interactions.parquet)
 
Скачайте их в директорию локального репозитория. Для удобства вы можете воспользоваться командой wget:

```
wget https://storage.yandexcloud.net/mle-data/ym/tracks.parquet
```

# Расчёт рекомендаций

Код для выполнения первой части проекта находится в файле `recommendations.ipynb`. Изначально, это шаблон. Используйте его для выполнения первой части проекта.

# Сервис рекомендаций

Код сервиса рекомендаций находится в файле `recommendations_service.py`.

Сервис рекомендаций состоит из трёх независимых FastAPI-приложений:

- **`recommendations_service.py`** (порт 8000) — основной сервис. Возвращает офлайн-, онлайн- и смешанные рекомендации.
- **`features_service.py`** (порт 8010) — сервис похожих треков (i2i), рассчитанных через ALS (`similar.parquet`).
- **`events_service.py`** (порт 8020) — хранит последние события (историю прослушиваний) пользователя в оперативной памяти.

## Стратегия смешивания online и offline рекомендаций

1. **Offline-рекомендации** — персональный топ-100 треков на пользователя, полученный через двухэтапный пайплайн (ALS-кандидаты → признаки → ранжирование CatBoost, `recommendations.parquet`). Если для пользователя нет персональных рекомендаций — используется топ популярных треков (`top_popular.parquet`).
2. **Online-рекомендации** — треки, похожие (i2i, ALS) на последние 3 трека из истории пользователя. Если у пользователя нет истории в `events_service` — online-список пуст.
3. **Смешивание** — списки чередуются поэлементно 1:1, начиная с online (online[0], offline[0], online[1], offline[1], ...), чтобы отдать приоритет свежему контексту сессии, не теряя стабильную персонализацию из offline-модели. Остаток более длинного списка добавляется в конец. Дубликаты убираются с сохранением первого вхождения. Итоговый список обрезается до `k` элементов.
4. Если один из списков пуст (нет истории или нет персональных рекомендаций) — итоговый список полностью соответствует другому источнику.

## Запуск сервиса

Активируйте виртуальное окружение и установите зависимости:

```bash
source env_recsys_start/bin/activate
pip install -r requirements.txt
```

Запустите все три сервиса, каждый в отдельном терминале (или в фоне через `&`):

```bash
uvicorn features_service:app --port 8010
```

```bash
uvicorn events_service:app --port 8020
```

```bash
uvicorn recommendations_service:app --port 8000
```

Дождитесь в логе каждого сервиса строки `Application startup complete.` — это означает, что данные (рекомендации, i2i-таблица) успешно загружены из S3.

После запуска сервис доступен по адресу `http://127.0.0.1:8000`, основные эндпоинты:

- `POST /recommendations_offline?user_id=<id>&k=<k>` — офлайн-рекомендации;
- `POST /recommendations_online?user_id=<id>&k=<k>` — онлайн-рекомендации на основе истории;
- `POST /recommendations?user_id=<id>&k=<k>` — итоговые смешанные рекомендации;
- `POST /stats` — статистика обращений к персональным/дефолтным рекомендациям (сервис `recommendations_service`);
- `POST /put?user_id=<id>&item_id=<id>` (сервис `events_service`, порт 8020) — сохранить событие прослушивания;
- `POST /get?user_id=<id>&k=<k>` (сервис `events_service`, порт 8020) — получить последние события пользователя;
- `POST /similar_items?item_id=<id>&k=<k>` (сервис `features_service`, порт 8010) — похожие треки.

# Инструкции для тестирования сервиса

Код для тестирования сервиса находится в файле `test_service.py`.

## Важно перед запуском тестов

`events_service` хранит историю событий пользователей в оперативной памяти процесса — состояние не сбрасывается автоматически между запусками `test_service.py`. Чтобы тестовые сценарии были воспроизводимы (особенно сценарий 2 — "пользователь без онлайн-истории"), перед запуском тестов рекомендуется перезапустить `events_service`:

```bash
# в терминале, где запущен events_service: Ctrl+C, затем
uvicorn events_service:app --port 8020
```

## Запуск тестов

Убедитесь, что все три сервиса (`features_service`, `events_service`, `recommendations_service`) запущены и готовы (см. раздел выше), затем выполните:

```bash
python test_service.py > test_service.log 2>&1
```

Проверьте результат:

```bash
cat test_service.log
```

## Что проверяет скрипт

`test_service.py` последовательно прогоняет три сценария и печатает в лог статус ответов сервиса, список рекомендованных `track_id` вместе с названиями треков и исполнителями, а также итог по каждому сценарию (`PASSED`/`ERROR`):

1. **Пользователь без персональных рекомендаций** (`user_id`, заведомо отсутствующий в `recommendations.parquet`) — проверяет, что сервис корректно откатывается на рекомендации по умолчанию (топ популярных).
2. **Пользователь с персональными рекомендациями, но без онлайн-истории** — проверяет, что при пустой истории событий итоговые (blended) рекомендации полностью совпадают с офлайн-рекомендациями.
3. **Пользователь с персональными рекомендациями и онлайн-историей** — скрипт предварительно отправляет несколько событий прослушивания через `/put`, затем проверяет, что итоговые рекомендации сочетают онлайн- и офлайн-источники.

Пользователи и треки для тестов подбираются автоматически из реальных данных (`recommendations.parquet`, `similar.parquet`), чтобы тест не зависел от жёстко заданных id, которые могут отсутствовать в конкретной версии данных.
